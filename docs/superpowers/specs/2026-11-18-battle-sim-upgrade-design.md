# 배틀 시뮬레이터 고도화 — 설계

## 의도
배틀 시뮬레이터를 없애지 않고, 자체 배틀 엔진(@kyasi/pokebattle-engine)의 능력을 화면에서 끝까지 보여 주는 포트폴리오 핵심 기능으로 키운다.
"엔진을 직접 만들었다"는 점이 드러나는 기능(재현 가능한 리플레이, 더블배틀, 배틀 분석)에 집중한다.

## 현재
- 싱글 배틀만: 팀 짜기(기술표·랜덤·Showdown 가져오기) → CPU와 대전 또는 CPU끼리 관전, 난이도 3단계, 테라스탈, 기술 버튼 데미지 범위.
- 배틀 로그 번역을 Pokestra가 직접 구현(`src/lib/battleLog.ts`, 664줄).
- 엔진은 이미 doubles/triples/rotation 형식과 random/heuristic/strong AI를 지원.
- 엔진 PR #5 머지 후: `createFormatter`(ko/en/ja 로그), 남은 HP 표시, 번들 8.7MB → 3.4MB.

## 단계 (각 단계가 독립적으로 배포 가능)
1. **엔진 업데이트 반영** (엔진 PR #5 머지 후)
   - 엔진 버전 올림, 자체 `battleLog.ts`를 엔진 `createFormatter`로 교체(시뮬레이터 화면·기능은 유지).
   - 엔진 세션의 데모 브랜치(`claude/eager-faraday-wmtt9o`)는 합치지 않는다. 필요한 API 사용 부분만 참고.
2. **배틀 화면(HUD) 개편** — 시선·동선 원칙 적용
   - 양쪽 포켓몬: HP 막대(남은 HP 숫자·% 전환), 상태이상, 능력치 랭크 칩(+2 공격 등), 테라스탈 타입.
   - 필드 줄: 날씨·필드·벽·스텔스록 등 남은 턴.
   - 기술 버튼: 타입, 남은 PP, 상대 기준 상성(효과 굉장/별로/없음), 예상 데미지 범위·확정 몇 타.
   - 로그: 턴별 접기, 중요한 사건(급소·기절·상성) 강조.
3. **리플레이와 공유**
   - 엔진이 시드로 결정적이라 "시드 + 양 팀 + 선택한 행동 목록"만으로 배틀 전체를 재현.
   - 배틀이 끝나면 링크 하나로 공유, 받은 사람은 같은 배틀을 턴 단위로 앞뒤 이동하며 재생(타임라인 슬라이더).
   - 서버 없이 URL(압축된 해시)만으로 동작.
4. **배틀 분석**
   - 배틀 후 요약: 포켓몬별 준 데미지·받은 데미지·쓰러뜨린 수, 턴별 남은 HP 흐름 그래프, MVP.
5. **더블배틀**
   - 엔진의 doubles 형식 사용: 기술 대상 선택 UI, 2 대 2 배치, AI도 더블로.
   - (트리플·로테이션은 비목표 — 엔진이 지원해도 이번엔 제외)

## 비목표
- 온라인 대전(사람 대 사람), 계정·랭킹, 서버 저장.
- 트리플·로테이션.
- 엔진 자체 수정(필요하면 엔진 세션에 요청 목록으로 정리).

## 실패로 볼 것
- 리플레이 링크를 열었는데 다른 결과가 나옴(재현 실패).
- HUD가 정보는 많은데 무엇을 봐야 할지 모르는 화면(6번 원칙: 한눈에 모르는 값엔 설명).
- 배틀 화면이 휴대폰에서 스크롤 없이는 기술 버튼을 못 누름.

## 접근 방식
- **단계별 고도화 (채택)**: 위 순서. 1은 엔진 머지에 묶여 있고, 2–4는 싱글 기준으로 먼저 완성, 5는 2–4의 화면 구조 위에 얹는다.
- 더블배틀부터: 화면 구조를 두 번 만들게 됨 → 기각.
- 엔진 데모 페이지로 교체: 사용자 결정으로 기각.

## 구현 쪽 결정 (Claude 판단)
- 리플레이 직렬화: `{v, seed, format, p1Team, p2Team, actions[]}`를 JSON → 압축(브라우저 `CompressionStream` deflate-raw) → base64url을 `#/battle/replay?d=...`에.
- 팀은 Showdown 텍스트 형식으로 직렬화(엔진 `exportShowdownTeam`/`parseShowdownTeam` 재사용).
- 분석 데이터는 엔진 이벤트(BattleEvent)에서 계산하는 순수 함수 + 단위 테스트.
- 앞선 밀도 개선 원칙(시선·마우스·읽기, 6번 원칙)을 그대로 적용.
