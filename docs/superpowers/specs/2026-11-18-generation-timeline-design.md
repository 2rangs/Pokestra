# 세대 타임라인 (포켓몬 상세 화면) — 설계

## 의도
다른 사이트에 흩어져 있는 "세대별 스프라이트 · 울음소리 · 세대별 변경점"을 상세 화면 한 곳에 모아,
세대 하나만 고르면 그 시절 모습이 한눈에 보이게 한다. 포트폴리오 차별점은 정보 자체가 아니라 **취합과 효율적인 표현**.

## 목표
- 상세 화면에 세대 선택 줄(I–IX). 고르면 머리말 스프라이트, 타입, 특성, 종족값이 그 세대 기준으로 바뀐다.
- 현재와 달라진 항목에 "N세대에 변경" 표시(예: 픽시 타입 노말 → 6세대에 페어리).
- 울음소리 재생 버튼: 최신 / 옛날 두 가지.
- `?gen=6` URL 파라미터로 공유 가능. 없으면 최신(현재와 같은 화면).
- 한국어·영어·일본어 문구.

## 비목표 (이번에 안 함)
- 여러 포켓몬을 모아 보는 "세대별 변경 목록" 화면, 도감 필터 (다음 단계 B안).
- 세대별 타입 상성표(1세대 고스트/에스퍼 등), 세대별 기술·배우는 기술 변화.
- 실전 능력치 패널, 기술 탭, 배틀/계산기는 현재 기준 그대로.

## 실패로 볼 것
- 세대를 바꿨는데 일부만 바뀌어 어느 세대 기준인지 헷갈리는 화면.
- 그 세대에 없던 포켓몬·특성·능력치를 있는 것처럼 보여 주는 것.

## 데이터 (전부 이미 불러오는 PokeAPI `pokemon/{id}` 응답 안)
- `past_types` / `past_abilities` / `past_stats`: 항목 `generation: N`은 "N세대까지는 이 값". 선택 세대 G에는
  `N >= G`인 기록 중 가장 이른 것을 쓰고, 없으면 현재 값.
- `past_abilities`의 `ability: null` = 그 슬롯이 그때 없었음.
- `cries.latest`, `cries.legacy` (.ogg).
- `sprites.versions[generation-x]`: `icons` 제외하고 `front_default`가 있는 첫 게임. 없으면 현재 기본 스프라이트.
- 등장 세대는 `species.generation`. 선택 줄은 등장 세대부터 IX까지만.

## 세대별 규칙
- 1세대: 특공/특방 대신 "특수" 한 칸(`past_stats`의 `special`).
- 1–2세대: 특성 영역에 "특성은 3세대부터" 안내.
- 3–4세대: 숨겨진 특성 없음.
- 울음소리: I–V세대 선택 시 옛날 울음소리를 먼저, VI 이상은 최신. 두 버튼 모두 항상 제공(옛날 것이 없으면 최신만).

## 접근 방식
- **A. 상세 화면에서 그때그때 계산 (채택)**: 새 데이터 파일 없이 이미 받는 응답으로 계산. 한 마리씩만 볼 수 있음.
- B. 세대 기록을 스크립트로 미리 모아 `src/data`에 저장: 모아 보기·필터 가능하지만 작업량 약 두 배. → 다음 단계로 미룸.
- 선택 이유: A가 바로 차별점을 보여 주고, B는 A 위에 얹을 수 있어 버리는 작업이 없음.

## 구현 쪽 결정 (Claude 판단, 수정 가능)
- 세대 계산은 순수 함수로 `src/lib/generation.ts`에 분리(`typesAt`, `abilitiesAt`, `statsAt`, `spriteAt`, `cryAt`).
  테스트를 위해 `vitest`를 개발 의존성으로 추가.
- 타입 상성 패널은 현재 상성표로 유지하고 "현재 기준" 표시(세대별 상성표는 비목표).
- 화면은 Astryx 컴포넌트로만(SegmentedControl/TabList 류, Badge는 개수 전용이라 변경 표시는 Text/Token 류).
- `PokemonDetail` 타입에 `past_types`, `past_abilities`, `past_stats`, `cries` 필드 추가.

## 빌더에게 남긴 것
- 세대 선택 줄의 정확한 컴포넌트, 변경 표시의 모양, 모바일 줄바꿈.
