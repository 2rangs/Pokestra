# 이미지 로딩 최적화 + 스켈레톤 — 설계

## 의도
사이트 전체 포켓몬 이미지가 로딩 중 빈칸·레이아웃 밀림 없이, 필요한 크기만 받아 빠르게 뜨게 한다.

## 현재
- 포켓몬 `<img>`가 약 20곳에 제각각. 일부만 lazy/크기 지정/실패 폴백.
- 28–40px 자리에도 475px 공식 일러스트를 받는 곳이 있음(예: `calc/PokemonPicker`).
- 이미지는 `raw.githubusercontent.com`(PokeAPI/sprites)에서 직접 → 서버 리사이즈 불가.

## 목표
- 공통 컴포넌트 `PokeImage` 하나로 통일:
  - 고정 크기(width/height) → 레이아웃 밀림 없음.
  - 로드 전 같은 크기 Astryx `Skeleton`, 로드 후 페이드인(테마 duration, 감속 모션 설정 시 즉시).
  - 실패 시 후보 URL 목록을 차례로, 모두 실패하면 빈 자리(`bg-muted`).
  - 기본 `loading="lazy"`, `decoding="async"`. `priority`면 eager + `fetchpriority="high"`.
  - 도트는 pixelated 렌더링.
- 크기별 소스 선택: 표시 크기 ≤ 64px → 도트 스프라이트 우선, 그보다 크면 공식 일러스트 우선.
- 상세 화면: 메인 아트워크 `priority`, 이전/다음 포켓몬 아트워크 미리 받기(유휴 시간).

## 비목표
- 이미지를 직접 리사이즈/변환해 저장소에 커밋(용량 문제).
- 타입 아이콘(로컬 SVG, `TypeIconDot`) 변경.
- 서비스 워커/오프라인 캐시.

## 실패로 볼 것
- 스켈레톤이 실제 이미지와 크기가 달라 로드 시 화면이 튐.
- 배틀 화면의 기절 애니메이션 등 기존 동작이 깨짐.

## 접근 방식
- **공통 컴포넌트로 교체 (채택)**: 한 곳에서 동작을 보장, 이후 기능(세대 타임라인)도 재사용.
- 각 호출부를 개별 수정: 중복이 남고 일관성 유지가 어려움 → 기각.
- 이미지 CDN/리사이즈 프록시 도입: 외부 서비스 의존 + 비용 → 기각.

## 구현 쪽 결정 (Claude 판단)
- 위치 `src/components/ui/PokeImage.tsx`, 소스 선택 헬퍼는 `src/lib/images.ts`.
- 크기는 `size`(px 숫자, 정사각형)로 받되 반응형 자리(`fluid`)는 부모 너비를 따르고 정사각 비율 유지.
- 단위 테스트 대신 빌드/린트 + 브라우저 확인(병행 작업이 테스트 도구를 추가 중이라 의존성 충돌 회피).
