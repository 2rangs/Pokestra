## 진단 (전)
- 일반 관리자 화면 같은 인상: 회색 바탕·흰 카드·검은 버튼, 도감의 정체성(번호·도감 설명·빨간 도감) 없음.
- 모바일: 헤더 두 줄(로고+언어 / 섹션 탭), 도감 목록이 2열 큰 카드라 한 화면 약 5마리, 기술 표가 가로로 잘림,
  홈 첫 화면이 바로 가기 카드로 차서 오늘의 포켓몬이 밀림, 언어 버튼 터치 영역이 헤더 밖으로 튀어나옴.
- 타입 표시가 세 가지(TypeTag 테두리형, TypeChip, 점)로 섞임. 홈 오늘의 포켓몬은 인라인 `color-mix` + raw div.

## 한 일
### 정체성: 도감 빨강 (테마)
- `npx astryx experimental theme editor set pokestra accent '#d8312a'` — editor 가 라이트/다크 음영과 대비를 맞춤
  (on-accent 흰 글자 4.78:1, text-accent 는 #b50b10 으로 4.59:1). 주 버튼·선택 탭·토글·포커스 링이 도감 빨강.
- 다만 목록의 이름 링크까지 빨개지면 시끄러워서, 행 전체가 링크인 자리(기술·도구·도감 표·배우는 기술·특성)의
  이름 링크는 `color="primary"`. 빨강은 "지금 여기·누를 것"에만.
- 상세 머리말: 도감 번호를 강조색·큰 글자·고정폭 숫자로, 도감 설명을 `Blockquote`(게임 도감 항목처럼).

### 모바일 (UX 우선)
- 헤더 한 줄(49px). 섹션 이동은 **아래 탭 줄**(lg 미만, 칸 56px, 엄지 영역, safe-area 고려). 선택 칸은 강조색 글자 + 위쪽 선.
- 섹션 아이콘은 게임 속 물건 도트: 몬스터볼(도감)·기술머신(기술)·특성캡슐(특성)·상처약(도구)·루브도(스프라이트). 넓은 화면의 TopNav 에도 같은 아이콘.
- 언어: 넓은 화면은 세그먼트, 좁은 화면은 44px 버튼 하나 + `DropdownMenu presentation="adaptive"`(휴대폰은 바텀시트).
- 도감 목록: sm 미만에서 카드가 **게임 도감 목록 같은 한 줄**(번호 · 40px 박스 아이콘 · 이름/보조 이름 · 타입) — 한 화면 약 9마리.
  같은 요소를 CSS 로만 바꿔 무한 스크롤 자리(data-slot)·"더 보기" 포커스 이동이 그대로 동작.
- 기술 표: sm 미만에서 타입·분류를 이름 아래로 합쳐 4열(이름·위력·명중·PP) — 가로 잘림 없음 (`useMediaQuery`).
- 홈: 좁은 화면에서는 바로 가기 숨김(아래 탭과 중복) → 오늘의 포켓몬이 첫 화면에.
- 스티키 오프셋 `top-12.25` 로 통일(PokedexFilterBar, ItemListPage). 맨 위로 버튼·푸터는 탭 줄 위로.

### 디테일
- 타입 표시 통일: TypeTag/TypeIconDot/typeColor 전부 `TypeChip`/`TypeGlyph` 로, 옛 컴포넌트와 raw hex `TYPE_COLOR` 삭제.
- 포켓몬 카드: 이미지 칸에 주 타입의 옅은 면(`subtle` 토큰).
- 홈: 오늘의 포켓몬을 Card + 타입 토큰 면/테두리로, 막대는 타입 색(0–200), 바로 가기에 도구 추가하고 히어로 빈 칸으로 이동,
  세대 카드 스타팅은 40px 박스 아이콘. raw div 를 Grid/VStack/HStack 으로.
- 공용 `StatBar`: SVG 로 다시 그려 인라인 style 제거, `fillClass` 로 타입 색.
- 기술 분류(물리/특수/변화): 의미 색 Token(주황/파랑/회색) — 목록·상세 머리말·배우는 기술 표.
- 도구 상세: 값은 굵게(수치는 large), 라벨은 기본 — 라벨/값 위계.
- 박스 아이콘 렌더링: SV 아이콘은 매끈한 렌더 그림이라 픽셀 렌더링 제외, 7세대 아이콘(40×30, 여백 큼)은 `scale-175` 로 칸을 채움
  (`isPixelSprite`/`isPaddedBoxIcon` → `src/lib/images.ts`, 테스트 포함). SV 아이콘은 SV 미등장 포켓몬(예: 꼬렛)에 404 → 7세대로 대체.

## Ruling
- **R1 강조색 = 도감 빨강**: 정체성의 핵심. 위험(danger)과 색상이 가깝지만 이 앱엔 파괴적 동작이 없고, 위험 버튼은 연한 톤이라 구분된다.
- **R2 빨강 절제**: 행 이름 링크는 primary. 빨강은 선택·주 행동·포커스·도감 번호에만.
- **R3 아래 탭 줄**: Astryx 에 하단 탭 컴포넌트가 없어 `nav` + react-router `Link` + Text 로 구성(토큰 유틸리티만). lg 이상은 기존 TopNav.
- **R4 모바일 도감 = 행**: 카드 DOM 을 그대로 두고 CSS 로 행 배치(중복 렌더링 없음, 접근성 이름·포커스 순서 동일).
- **R5 기존 결정 유지**: 상세의 타입 색 막대(0–200 고정 눈금)·머리말 구조는 밀도 트랙의 결정이라 건드리지 않음(설계의 "값 구간별 색"은 적용 안 함).
- **R6 다크 모드**: 앱이 라이트 고정(`mode="light"`)이라 이번 패스는 라이트만 확인. 토큰은 다크 값도 있음.

## 남은 것 (제안)

## 2차 (11-24, 이어서)

### 사용자 피드백
- "바탕에 속성색 넣지 마" → 카드 이미지 칸·상세 머리말·오늘의 포켓몬의 타입 색 면/테두리를 모두 제거(중립 `bg-muted`/기본 카드).
  타입 색은 이제 **타입 배지에만** 쓴다.
- "UI/UX 별로, 레딧/인터넷 찾아서 최적으로" → 아래 조사 후 반영. (reddit.com 은 이 환경의 검색 도구에서 차단돼 직접 인용 못 함)

### 조사 요약 (근거)
- 커뮤니티: Serebii·PokémonDB 는 "빠르고 한 페이지에 다 있어서" 선호, Bulbapedia 는 "끝없는 스크롤·군더더기·광고"로 비판
  ([PokéCommunity: Serebii or Bulbapedia?](https://www.pokecommunity.com/threads/serebii-or-bulbapedia.452348/page-2)).
- HN 의 도감 웹앱 피드백: 모바일 호환·속도·뒤로가기 동작이 반복된 불만
  ([Pokedex.org](https://news.ycombinator.com/item?id=10619933), [Anidex](https://news.ycombinator.com/item?id=41720288)).
- 목록 vs 그리드: 찾기(조건 검색)는 목록, 둘러보기는 그리드. 모바일은 목록이 한 화면에 더 많이 담는다
  ([UX Planet](https://uxplanet.org/mobile-ux-design-list-view-and-grid-view-8f129b56fd5b), [babich.biz](https://babich.biz/blog/mobile-ux-design-list-view-and-grid-view), [NN/g](https://www.nngroup.com/articles/image-vs-list-mobile-navigation/)).
- 도감 사이트의 관례(PokémonDB 등): 흰 바탕 + 색은 타입 배지에만, 종족값 막대는 **값 구간별 색**, 도감 설명은 **작품별 목록**.

### 반영
- **종족값 막대 = 값 구간별 색** (30·60·90·120·150 경계, 빨강→주황→노랑→연두→초록→청록). 타입 색 막대 제거.
  색은 테마 토큰 `--pokestra-stat-1..6`(라이트/다크) + 브리지 `src/stat-colors.css`, 함수 `src/lib/statBand.ts`(테스트).
  상세 차트·홈 오늘의 포켓몬 공통. 범례의 "선택한 세대" 견본은 중립색.
- **작품별 도감 설명**: 최신 작품 설명을 인용 블록 + 출처(예: "포켓몬스터 실드 · Y" — 같은 글은 작품을 묶음),
  나머지는 "다른 작품의 도감 설명 N개" 접힘 목록(`src/lib/flavorEntries.ts`, 작품 이름 `src/lib/gameNames.ts`, 각각 테스트).
- **상세 "기술" 탭 표(모바일)**: 타입·분류를 기술 이름 아래로, 숫자 칸은 내용 폭 — 가로 잘림 없음.
- **화면 모드**: 헤더의 아이콘 메뉴(기기 설정/밝게/어둡게, localStorage 저장, `src/stores/colorModeStore.ts`, `src/components/ThemeRoot.tsx`).
  html 의 `color-scheme` 도 맞춰 스크롤바·바깥 면이 같은 모드.

### Ruling (추가)
- **R7 바탕 타입 색 금지**: 사용자 결정. 타입 색 토큰의 `subtle`/`border` 는 남겨 두지만 화면에서 쓰지 않는다.
- **R8 막대 색은 값의 의미**: 밀도 트랙의 "타입 색 한 가지" 결정을 뒤집음 — 도감 사이트 관례이고, 막대만 보고 강점·약점을 읽게 한다. 숫자가 늘 옆에 있어 색만으로 정보를 전달하지 않는다.
- **R9 다크 모드 기본 = 기기 설정**.

## 3차 (11-24): 미니멀 정리 — 사용자 피드백 "타입 가시성 별로, 미니멀이면 미니멀하게, 카드 안 정보 구분 없음"
- 시안 3개(A 진한 단색+흰 글자 / B 색 아이콘+이름 / C 밝은 색+단색 문양)를 렌더링해 비교 → **사용자 선택: A**.
- **타입 배지**: 모든 타입이 진한 단색 + 흰 문양 + 흰 굵은 글자, 모서리 6px(`--radius-inner`). 흰 글자 대비 4.5:1 에 맞춰 명도를 낮추고
  채도를 1.15배(색역 안). 전기·불꽃·벌레는 색역 한계로 올리브·갈색 기운이 남는다(시안에서 확인된 대로).
  문양은 `public/assets/types/*.svg` 에서 바탕 원을 뺀 모양(`src/components/ui/typeGlyphs.ts`, `TypeMark`).
- **나머지는 흑백**: 강조색을 neutral 로 되돌림(editor `undo accent`), 배수는 굵기·글자색으로, 분류는 글자, 전설·숨겨진 특성 등 Token 은 기본색.
- **예외 — 종족값 막대**: 흑백으로 바꿨다가 사용자 피드백("색이 똑같아서 별로")으로 **값 구간별 색 복원**. 색이 높낮이를 뜻하므로 "색은 타입에만"의 유일한 예외.
- **카드 안 정보 구분**: 상세 머리말은 신원(번호·이름·타입·분류) / 핵심 수치 / 조작 / "도감 설명" 묶음을 구분선으로, 타입은 이름 바로 아래.
  특성 카드와 정보 목록(FactList: 종 정보·교배·기술 상세)은 행마다 얇은 구분선 + 값 굵게. 오늘의 포켓몬은 신원과 능력치 사이 구분선.

## 4차 (11-24): 사용자 피드백 연속 반영
- **도감 설명은 작품마다 다르다** → 도감 설명 옆 작품 선택(같은 글은 묶음, 예: "썬 · 문"). 머리말의 세대 선택과 연동(그 세대 작품 설명이 기본).
  사용자 언어 설명이 없는 옛 작품은 영어 설명 + "한국어 설명 없음 (영어)" 표시. `src/lib/flavorEntries.ts`(`buildFlavorOptions`, `defaultFlavor`), 작품→세대 `versionGeneration`.
- **기술 목록 공백** → 이름 칸 200px 고정, 남는 자리는 맨 오른쪽 "설명" 열(효과 한 줄, 넘치면 말줄임).
- **"사용할 수 없는 기술입니다"** → Z기술과 대조: 135개 중 Z기술 53개(데이터의 Z기술 전부), 레츠고 전용기 14개, 나머지는
  소드·실드에서 빠진 일반 기술(태권당수·소닉붐 등). 원인은 데이터가 최신 설명(소드·실드의 안내문)만 담은 것 →
  `scripts/fix-move-descs.mjs` 로 PokeAPI 에서 안내문이 아닌 최신 설명을 언어별로 골라 405개 교체(남은 안내문 0).
- **도감 카드가 어지럽다** → 회색 이미지 칸·영어 보조 이름 제거, 타입 한 줄, 정렬 값은 번호 옆. 카드 내용은 가운데 정렬(그림과 같은 축).
- **종족값 분포** → 능력치·합계마다 "상위 N%"(폼 제외 전체 종의 현재 값 기준, 같은 값은 같은 순위). `src/lib/statRank.ts`(테스트), 툴팁·ⓘ 설명 포함.
- **글자 크기** → 테마 editor `text-size larger`(본문 16px) + `--font-size-sm` 14px(보조 글자). 폰(터치 1024px 미만)은 원래 16/14px.
- **타입·이름 글자가 어색** → Token sm(높이 20px)에 14px 굵은 글자가 눌려 보였음 → TypeChip 의 Token 크기를 한 단계 위로(sm→md, md→lg), 굵기 bold→semibold.

## 5차 (11-24): 도감 화면 재설계 — "도감 UI/UX 최악, 카드 디자인 최악"
- 실제 데이터로 시안 3개(A 갤러리 카드 / B 표 / C 목록+미리보기)를 렌더링해 비교 → **사용자 선택: A + 새 필터 바**.
- **카드(A)**: 한 줄 최대 6개(최소 폭 180px), 옅은 판 위 128px 그림 → 번호(+정렬 값) → 굵은 이름(large) → 타입. 왼쪽 정렬.
  모바일은 같은 요소가 한 줄(박스 아이콘 · 번호/이름 · 타입). 무한 스크롤 자리 높이 갱신(sm:h-72 / h-17).
- **필터 바**: 1줄 = 큰 검색 · 타입(여러 개, 아이콘+이름 목록) · 세대 · 기술 · 정렬+방향 버튼(모두 44px 높이).

- **뒤로 가기 위치 복원** (`src/hooks/useScrollRestoration.ts`): 새 화면은 맨 위, 뒤로·앞으로는 떠날 때 위치(화면 기록별, sessionStorage).

## 7차 (11-24): 홈 재구성 — "빈 공간 많음, 구조를 바꾸든지", "똑같은 게 너무 많다, 혁신적인 거 없냐"

같은 카드 줄(종족값 TOP·전설·최신 세대·세대별)을 반복하던 탐색 허브(C안)를 버리고, 들어오는 방법이 서로 다른 세 덩어리로 바꿨다.

- **실루엣 퀴즈** (`components/home/SilhouetteQuiz.tsx`, 순수 로직 `quizModel.ts` + 테스트)
  - 날짜로 정해지는 오늘의 문제(모두 같은 포켓몬), "다른 문제"는 무작위.
  - 세 언어 이름 또는 한국어 이름의 초성을 정확히 입력하면 정답. 힌트: 타입·세대. 정답 보기.
  - 맞히거나 정답을 보면 실루엣(`brightness-0`)이 그림으로 바뀌고 "도감에서 보기".
  - 오늘의 문제를 연달아 맞힌 날 수(localStorage, 막혀도 동작).
- **찾아보기 카드**: 검색(Typeahead) · 자주 찾는 포켓몬 · 타입 칩(종 수) · 세대 칩 → 필터가 걸린 도감으로.
- **종족값 지도** (`components/home/StatMap.tsx`)

  - 점 크기 = 종족값 합계, 색 = 타입. 타입을 고르면 그 타입만 진하게, 나머지는 회색으로 흐리게.
  - 강조된 것 중 합계 상위 3마리 이름표(겹치면 오른쪽→왼쪽→위→아래로 자리 이동, 강조 고리도 장애물).
  - 점에 올리면 이름·수치, 누르면 상세. 그림은 칸 너비의 실제 픽셀로 그려 모바일에서도 글자 크기가 같다(좁으면 정사각형에 가깝게).
- 홈에서 쓰지 않게 된 줄·배너 코드는 지웠다.

## 8차 (11-24): 인게임 스프라이트를 크게 — "다 작네, 원본 사이즈처럼"

- `ui/PixelSprite`: 도트의 원본 크기를 읽어 칸(192px)에 들어가는 가장 큰 정수배로 그린다(96px → 2배, 56·64px → 3배). 픽셀이 고르게 커지고 흐려지지 않는다. 박스 아이콘은 2배까지만.
- 스프라이트 페이지: 도트 보기는 카드마다 2배(최대 5열, 모바일 2열·144px). 상세의 스프라이트 탭: 게임·세대별 도트 모두 192px 칸.
- 폼 선택을 개요 탭 맨 아래 패널에서 머리말 그림 바로 아래로 옮겼다(`DetailHeader imageFooter`). 4개 이하는 칩, 그보다 많으면(피카츄 17개 등) 그림 붙은 목록 선택. 휴대폰에서는 이름 줄 다음 한 줄 전체.
- 폼 선택을 다시: 칩·드롭다운 대신 **폼마다 그림 타일**(지금 폼은 테두리, 올리면 위 줄에 이름). 폼이 많아도 한눈에, 모양으로 고른다.

## 10차 (11-24): 종족값 지도 — "능력치를 자유롭게", "더 직관적으로"

- 축을 사용자가 고른다: 6가지 능력치 + 공격력(공격·특공 중 높은 값) + 합계(100–800 눈금). 가로·세로 바꾸기 버튼.
- 처음 보는 사람용: 축 고르기를 문장으로("→ 오른쪽일수록 높은 [공격력] · ↑ 위쪽일수록 높은 [스피드]"), 추천 비교 버튼(빠른 공격수·단단한 방어형·체력과 방어·강한데 빠른), 그림 네 귀퉁이 뜻(둘 다 높음 / ○○만 높음 / 둘 다 낮음), 범례 한 줄.
- 브라우저 기본 말풍선 대신 정보 카드(그림·이름·타입·두 값·합계). 데스크톱은 올리면 카드·누르면 상세, 휴대폰은 탭하면 카드 + "상세 보기".

## 11차 (11-24): 상위 %를 소수 첫째 자리까지, 1위는 단독·공동 표기

- `statRank(key, value)` → `{ rank, tied, percent }`. percent 는 소수 첫째 자리까지 올림(5위/1,025종 → 0.5%), 표시는 항상 한 자리("상위 4.0%").
- 1위는 %(0.1%) 대신 "단독 1위"(해피너스 HP 255, 아르세우스 합계 720) / "공동 1위"(말풍선에는 몇 마리인지).
- 아래쪽 절반은 "상위 99.7%" 대신 **"하위 0.3%"**(아래에서 센 순위), 맨 아래는 "최하위"/"공동 최하위". `rankLabel()` 이 first/top/bottom/last 를 고른다.
- 말풍선·스크린리더에는 순위를 문장으로: "공격 10 · 1,025종 중 1,021위 (하위 0.3%)", "HP 255 · 1,025종 중 단독 1위".
